# uBixOS 3.1.0 — release notes

**Headline: uBixOS now builds itself.** On both supported architectures
(aarch64 and x86_64) the system rebuilds its own world and kernel inside
uBixOS, and an image made from that output boots on the self-built kernel and
passes `sigtest` and `vfstest` (W-007, 2026-10-14).

## Self-hosting (W-007)

| | aarch64 | x86_64 |
|---|---|---|
| In-OS `bmake -j4 world` (clean, 4 vCPUs) | passes, 3h44m | passes, 9h48m (QEMU TCG) |
| In-OS `bmake -j4 kernel` | passes | passes |
| Self-built kernel boots; `sigtest` + `vfstest` | pass | pass |
| Image made only from the in-OS build output boots on it; `sigtest` + `vfstest` | pass | pass |

Caveats, as tested:

- The in-OS toolchain is Clang/LLVM + lld (the LLVM port, host-built).
- The image test used in-OS build output plus the host-built LLVM port and
  host-built `sh` and `bmake`. From W-053 `world` builds `sh` and `bmake`
  itself; the whole-image test above predates that change.
- NetSurf is skipped in-OS: it is a port that needs GNU make.
- Re-stage `/usr/src` (`tools/stage-src.sh`) before in-OS builds, or the in-OS
  libc is built from stale sources.

## What made it possible

- **W-043 — musl builds with `bmake`.** `contrib/musl/Makefile.bsd` builds the
  same 1355 objects with the same flags as the GNU build, so `/usr/src/lib`
  builds in-OS with the BSD toolchain. In-OS `bmake -j4 musl-libc` takes about
  2h11m on aarch64 and its `libc.so` passes `sigtest` and `vfstest`.
- **W-045 — bare in-OS `clang` links programs.** `crtbeginS.o`/`crtendS.o` are
  built from compiler-rt (`lib/crtbegin`) on both arches and staged into
  `/lib`; `clang -o h h.c` links in-OS.
- **W-050 — physical page leak per exited process fixed.**
  `mmap(MAP_FIXED)` over a live page dropped the old frame without freeing it
  (musl mallocng's heap guard page lost one page per process). Now released on
  both arches. 500 `ls` on aarch64: `MemUsed` flat (was ~4 KB per process);
  300 on x86_64: +188 KB (was ~1.36 MB).
- **W-051 — programs linked in-OS are executable.** `open(O_CREAT)` applies
  the mode, `chmod`/`fchmod` work, `rename` is a native atomic entry move that
  keeps mode and data; `O_EXCL` gives `EEXIST`.
- **W-052 — real `umask(2)`.** Per-task mask; inherited by `fork`/`rfork`
  threads, kept across `exec`, applied by `open(O_CREAT)`. Known limit:
  `mkdir` still ignores its mode (directories are always 0755).
- **W-053 — `/bin/sh` and `bmake` are built by `world`.** `oksh` 7.5 and
  `bmake` 20240212 are vendored in `contrib/`, so a world built inside uBixOS
  rebuilds its own build tools.

## VFS lookup cache (W-039)

A profile of the in-OS kernel build showed `vfs_io_lock` held 92-96% of the
time, mostly by uncached path walks (`readlink()` from `realpath()`, about
40,000 per build, all on ordinary files). `sys/fs/vfs/file.c` now caches
"missing" and "exists, not a symlink" per canonical path on UbixFS mounts
(2048 entries); create, unlink, rename, mount and unmount invalidate it.

| Clean in-OS `bmake -j4 kernel` | before | after |
|---|---|---|
| aarch64 (HVF) | 138.6 s | 86.4 s |
| x86_64 (TCG) | 980.4 s | 483.1 s |

`stat` still walks the path once per file and the lock is still mostly
saturated (writes, `stat`); further steps are in
`docs/design/vfs-lookup-perf-plan.md`. `tests/vfstest` covers the cache.

## Version

`UBIXOS_VERSION_TAG` is now empty; the release string is `3.1.0` (no
