**Notes:** tcsh 6.24.16 is working interactively. Verified 2026-06-03: `~`
expands to `$HOME` (`/home/root`); `/etc/csh.cshrc` auto-loads in every
interactive shell (its `ls`/`ll`/`..`/`h` aliases are active).

**Login shells (macOS Terminal.app model):** every interactive tcsh is a *login*
shell, so it sources the login files (`/etc/csh.login`, `~/.login`) as well as
the per-shell rc (`/etc/csh.cshrc`, `~/.tcshrc`). Two launch paths set this up:
- **Console** (serial/VGA): `bin/login` execs the shell with `argv[0]="-tcsh"`.
- **GUI terminal** (`bin/views/term/term.cc`): execs `argv[0]="-tcsh"` too —
  built as `"-" + basename(SHELL)`, mirroring `bin/login`. (Changed 2026-06-03
  from a non-login launch; chosen over the Linux model of sourcing login files
  once in `vlogin`, for simplicity on a single-user system.)

Verified in a GUI terminal: `$?loginsh` = 1, `$BLOCKSIZE` = K (from `csh.login`),
`ll` alias active (from `csh.cshrc`), `~` → `/home/root`. Note `$HOST` reflects
the kernel hostname via `gethostname()`, not `csh.login` — a separate, cosmetic
hostname-naming inconsistency (kernel says `ubixos`; login/csh say
`Dev.uBixOS.com`), unrelated to the tcsh port.

**Prerequisite:** Complete the musl libc / libcpp migration and remove the old libc first.

## Before Starting — Kernel Prerequisites

Do not begin the port until these are verified working under QEMU:

- `tcsetpgrp(fd, pgrp)` — sets the foreground process group on the TTY
- `SIGCHLD` delivery to the correct process group when a child exits or stops
- `waitpid(pid, &status, WUNTRACED)` — returns on stop, not just exit
- `SIGTSTP` / `SIGCONT` — sent and delivered correctly for `^Z` / `fg`

If job control is broken in the kernel, tcsh will appear to work but `^C`, `^Z`, and background jobs will misbehave regardless of the libc. Fix the kernel first.

## Steps

### 1. Get a clean source snapshot

```sh
# In contrib/:
curl -LO https://astron.com/pub/tcsh/tcsh-6.24.10.tar.gz
tar xf tcsh-6.24.10.tar.gz
mv tcsh-6.24.10 contrib/tcsh
git add contrib/tcsh
git commit -m "contrib/tcsh: import 6.24.10 unmodified"
```

### 2. Generate config headers on the host

Run `./configure` on a Linux/macOS host with an i386 cross target to produce the generated headers. Capture and commit them as `contrib/tcsh/ubixos_config/`:

- `config.h` — feature-test results
- `tc.const.h`, `tc.decls.h`, `sh.err.h`, `sh.func.h`, `sh.char.h` — generated by tcsh's own scripts (`makelist`)

These replace the autoconf step at build time — same pattern used for musl and tcc.

```sh
mkdir contrib/tcsh/ubixos_config
# copy generated headers here
git add contrib/tcsh/ubixos_config
git commit -m "contrib/tcsh: add UbixOS pre-generated config headers"
```

### 3. Write bin/tcsh/Makefile

Drive the build directly from bmake, similar to `bin/tcc/Makefile`:

- Include paths: `contrib/tcsh/ubixos_config/` first, then musl headers, then `include/`
- Compile all `.c` files in `contrib/tcsh/` with `-DUSE_PREGENERATED_CONFIG`
- Link with `ubix.musl.ubix.prog.mk` (needs MPI + `ubix_getcwd` for prompt)

### 4. Stub missing pieces

These will likely need a `bin/tcsh/ubixos_compat.c`:

| Symbol | Resolution |
|--------|-----------|
| `tgetent`, `tgetstr`, `tputs` | Minimal hardcoded vt100 termcap stub — tcsh only needs cursor movement and clear-to-EOL for line editing |
| `getpwuid`, `getpwnam` | musl provides the API; needs `/etc/passwd` in standard format on the image (convert `tools/userdb` or add a separate `/etc/passwd`) |
| `sigaction` with `SA_RESTART` | Audit kernel — may need a fuller implementation |
| `opendir`/`readdir` | musl provides; verify VFS returns correct `d_type` for tab completion |

### 5. Wire into the build and image

```makefile
# bin/Makefile — add tcsh to SUBDIRS
SUBDIRS = ... tcsh ...
```

```sh
# tools/mkimage.sh — install tcsh
mcopy build/bin/tcsh ::bin/tcsh

# tools/userdb — set login shell for root
# Change /bin/shell -> /bin/tcsh in the shell field
```

### 6. Testing checklist

- [x] Starts and prints a prompt
- [x] Tab completion works for filenames
- [x] Command history (`↑`/`↓`) works
- [x] `^C` kills the foreground command (not tcsh itself)

- [x] Background jobs (`command &`) work
- [x] `~` expansion resolves correctly
- [x] `/etc/csh.cshrc` loads on startup (+ `/etc/csh.login`, since shells are login shells)
